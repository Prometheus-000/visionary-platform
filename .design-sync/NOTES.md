# design-sync notes — visionary_platform

## What this repo is, and what the sync had to build

`visionary_platform` is a Modal application, **not** a design system. `web/` is a
private Vite app: no Storybook, no stories, and `web/dist/` is an app bundle
(index.html + hashed js/css), not a component library.

So the first sync **created the library entry**, additively — no existing app
file was rewritten:

| File | Why |
|---|---|
| `web/src/ds/index.ts` | the barrel. Its own comment carries the test for what belongs: does the component know anything about Visionary? The five in `web/src/ui/` do not; `Console`, `Canvas`, `Card`, `Editor` etc. read the zustand store, the API client and the job lifecycle, so they are the app rather than the system. |
| `web/vite.lib.config.ts` | lib build → `web/dist-ds/`, React external, one stylesheet |
| `web/tsconfig.ds.json` | declaration-only emit → `dist-ds/types/` |
| `web/build-ds.mjs` | the three steps in the one order that works (below) |
| `web/package.json` | added `module`, `types`, and the `build:ds` script |

Rebuild with `npm --prefix web run build:ds` (this is `cfg.buildCmd`).

## Gotchas, each of which cost a cycle

- **`vite build` must run before `tsc`.** The lib config uses `emptyOutDir`, so
  declarations emitted first are deleted by it. That ordering is why
  `build-ds.mjs` exists instead of an `&&` chain in package.json.
- **tsc copies `import '../styles/ui.css'` into the emitted `.d.ts`**, where it
  resolves to nothing. `build-ds.mjs` strips that line and writes the sibling
  `dist-ds/index.d.ts` the converter looks for beside the entry.
- **The converter needs `types` in package.json.** Without it, `exportedNames`
  looks for `web/index.d.ts`, finds nothing, and the run ends in `[ZERO_MATCH]
  — treating as tokens-only DS` with 0 components. That failure names nothing
  about package.json, so it reads as a broken barrel.
- **`cfg.dtsPropsFor` is load-bearing for 4 of 5 components.** The extractor
  dropped `| null` from `anchor` (which is the *closed* state, and exactly what
  `usePopover()` returns), and emitted `MenuItem`, `ApiError` and
  `CSSProperties` as bare references with no import — so those `.d.ts` were not
  valid TypeScript. The hand-written bodies are self-contained on purpose.
- **`ui.css` is regenerated byte-for-byte by `tools/extract_css.py`.** Never
  edit it. The lib entry imports it rather than copying it, for that reason.

## Previews

- **The card harness paints `body{background:#fff}` after `styles.css` loads.**
  Visionary is black-only, so every preview paints its own ground via a local
  `Dark` wrapper. Deliberately *not* fixed with `!important` in the shipped CSS —
  that would force every real design built with the DS onto a black `body`.
- **`.ds-cell` / `.ds-single` carry `transform:translateZ(0)`**, which makes the
  cell the containing block for `position:fixed` descendants. That is what keeps
  the portalled `Popover`/`Menu`/`Sheet` inside the card — and it means a ground
  styled `position:fixed;inset:0` collapses to nothing. Use a normal-flow block
  with `minHeight:'100vh'`.
- **`.opt.ib` is the icon-button variant with `width:var(--ib)`** and squeezes a
  text label to nothing. A labelled control is plain `.opt`.
- **`overrides.<Name>.viewport` is product-card metadata only.** `validate`
  always screenshots at 1200x800 and `capture` at 900x700, so a story that fits
  the product card can still be clipped in the review sheet. Two cells had to be
  trimmed for this (`Menu/WithSeparatorAndDanger`, `Popover/ModelList`).

## Known render warns

- **`Sheet` cards show a thin grey edge** where the `.scrim`
  (`rgba(0,0,0,.72)`, `position:fixed`) laps the cell padding outside the
  preview's own dark ground. Cosmetic; content is complete and correctly styled.
  Graded `good` deliberately.

## Re-sync risks

- **A new primitive in `web/src/ui/` will not sync until it is exported from
  `web/src/ds/index.ts`.** There is no globbing — the barrel is the contract,
  and nothing warns about an omission.
- **`tools/extract_css.py` regenerating `ui.css` rewrites `_ds_bundle.css`
  wholesale**, so styling re-verifies. More importantly the five previews depend
  on app classnames (`.opt`, `.frow`, `.menu form`, `.sheet-head`, `.sess-acts`,
  `.err-box`). If a regeneration drops one, the cards degrade **silently** — the
  render check only fails an *empty* root, not an unstyled one. Look at the
  contact sheet after any `extract_css.py` run.
- **`conventions.md` enumerates real tokens and classnames** (all verified
  against `_ds_bundle.css` at authoring time). A token rename in `ui.css` makes
  the header lie to the design agent. Re-validate the names, don't assume.
- **React is external**; preview cards load React 19 from `_vendor/`.
- **Not verified**: nothing here was checked against a light theme, because the
  DS has none, and no responsive/breakpoint behaviour was exercised.
